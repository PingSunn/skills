ps-factory

An agent team for coding work. One Orchestrator per project, a Lead per Story, and a Dev + QA pair per Slice — on Orca or Herdr.

You talk to one agent. The team builds, reviews and reports back.

1 · The roles

Who does what

Yougive every instruction to the Orchestrator
Orchestrator Opusone per project · routes work · keeps the Story Ledger · the only one that reports to you
Lead Opusone per Story · splits it into Slices · settles Dev–QA disputes
Dev Sonnetone per Slice · own worktree · opens a Slice PR
QA Opusone per Slice · traces real code paths · never edits code

Dev and QA talk to each other directly. Reports go up one level at a time.

Install and init

3 · One Story, end to end

"Retry failed LINE sends 3 times and show it in admin"

  1. Orchestrator routes it: no open Story matches → opens line-retry, confirms acceptance criteria with you
  2. Lead cuts feat/line-retry, splits it into Slices: api, ui
  3. Each Slice gets a Dev in its own worktree and a QA; the Lead introduces them
  4. Dev opens a Slice PR → QA: fail with findings → Dev fixes → pass
  5. Slice PR merges into the Story Branch (Lead or you, per Project Policy)
  6. All Slices in → Story PR into the Target Branch → a fresh QA checks the whole Story
  7. Orchestrator tells you it is ready, with evidence. You merge, then confirm closing it.
4 · Branch strategy

Nothing lands on the Target Branch directly

Target Branch (main / dev)
feat/line-retry (Story Branch)
slice: api
slice: ui
Slice PR #1 ↑ QA pass
Slice PR #2 ↑ QA pass
Story PR ↑ whole-Story QA · you merge

Small reviews, parallel Devs, and the Target Branch stays untouched until you accept the whole Story.

5 · Memory that survives /clear

Context is a cache; disk is the truth

Write-aheadOrchestrator and Lead update their state files before replying or messaging anyone
State filesledger.md · decisions.md · archive.md · stories/<story>.md — outside the repo, same path from every worktree
SessionStart hookafter compact / clear / resume, puts the ledger (Orchestrator) or Story Notes (Lead) back
Clear at checkpointsthe Orchestrator says "Checkpoint: safe to /clear." — auto-compact is only the safety net
Refresh Leadsa fresh Lead resumes from the Story Notes every 3 merged Slices and after story-ready
Short-lived workersDev and QA close when their Slice passes
6 · What reaches you

Only four kinds of report

needs-decisiona question only you can answer, with the Lead's recommendation
awaiting-mergea PR the Project Policy says you merge
story-readythe Story PR, its Slices and the QA evidence
blockedwhat blocks, what was tried, what would unblock it

Everything else — Fix Loop rounds, Slice progress — stays inside the Story. Check the Orca cards if you want to watch.
